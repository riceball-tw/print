## 前言

快照測試適合穩定的輸出，卻不適合每週都在變動的介面。文章分析三個實際發生的失敗案例，再把它們改寫成重構後依然有意義、能表達意圖的斷言。

## 現場筆記

在處理 Software Testing 問題的過程中，反覆看到的幾個模式：

- 簡單的版本撐過了每次重構，聰明的版本沒有。
- 邊做邊寫的文件，比事後補寫的耐用得多。
- 同一個問題第二次出現時，它就已經是模式了——幫它命名吧。

## 可以直接抄的檢查清單

- [ ] 問題可以用一行指令重現。
- [ ] 修正附帶一個沒有它就會失敗的測試。
- [ ] 作者本人以外的人也在自己的機器上跑過。

## 結語

寫下未來的自己真的會讀的短版本——這就是全部的訣竅。
