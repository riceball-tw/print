## 前言

不穩定的測試會訓練團隊忽略紅色的建置結果。這份清單包含自動偵測 flaky 測試、指派負責人的隔離通道，以及造成多數問題的四種根本原因。

## 現場筆記

在處理 Software Testing 問題的過程中，反覆看到的幾個模式：

- 簡單的版本撐過了每次重構，聰明的版本沒有。
- 邊做邊寫的文件，比事後補寫的耐用得多。
- 同一個問題第二次出現時，它就已經是模式了——幫它命名吧。

## 可以直接抄的檢查清單

- [ ] 問題可以用一行指令重現。
- [ ] 修正附帶一個沒有它就會失敗的測試。
- [ ] 作者本人以外的人也在自己的機器上跑過。
