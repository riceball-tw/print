## 前言

密钥在公开仓库里躺了九天，实际上推送后几小时内就被爬走。文章记录了检测、轮换、缩小权限范围的过程，以及事后补上的 pre-commit 与 CI 检查。

## 核心心智模型

- 从最小可运行的版本开始，并让它可观测。
- 把你正在承担的取舍写下来，而不只是写下交付了什么功能。
- 团队规模变化时重新审视决策；Cybersecurity 里的多数选择都有保质期。

## 动手起点

1. 在实验分支重现问题，放在你信得过的度量指标旁边。
2. 一次只改变一个变量，让 diff 小到能用一句话解释清楚。
3. 保留成果，丢掉脚手架。

```bash
git switch -c experiment/one-thing
```

## 写在最后

这里没有教条。把它当作一份你有权不同意的检查清单——最好附上你自己的实验结论。
