## 前言

并不是每个 Astro 项目都需要服务器，也不是每一页都该是静态的。文章以一次真实的博客迁移为例，比较预渲染、按需渲染与混合部署的取舍。

## 核心心智模型

- 从最小可运行的版本开始，并让它可观测。
- 把你正在承担的取舍写下来，而不只是写下交付了什么功能。
- 团队规模变化时重新审视决策；Astro 里的多数选择都有保质期。

## 动手起点

1. 在实验分支重现问题，放在你信得过的度量指标旁边。
2. 一次只改变一个变量，让 diff 小到能用一句话解释清楚。
3. 保留成果，丢掉脚手架。

```bash
git switch -c experiment/one-thing
```

## 写在最后

这里没有教条。把它当作一份你有权不同意的检查清单——最好附上你自己的实验结论。
