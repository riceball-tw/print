## 前言

两百个 Cypress 用例在纸面上有覆盖率，实践中却要跑四十分钟。我们保留保护营收的用户旅程、把其余下移到测试金字塔底层，并定下规则防止套件再次膨胀。

## 核心心智模型

- 从最小可运行的版本开始，并让它可观测。
- 把你正在承担的取舍写下来，而不只是写下交付了什么功能。
- 团队规模变化时重新审视决策；Software Testing 里的多数选择都有保质期。

## 动手起点

1. 在实验分支重现问题，放在你信得过的度量指标旁边。
2. 一次只改变一个变量，让 diff 小到能用一句话解释清楚。
3. 保留成果，丢掉脚手架。

```bash
git switch -c experiment/one-thing
```
